## 2. Igris_brain (backend, FastAPI)

```bash
cd Igris_brain
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
# MCP server'lari (FastMCP) va server uchun qo'shimcha:
pip install fastapi uvicorn mcp fastmcp
# ixtiyoriy xotira (RAG/BM25/FAISS):
pip install ".[memory]"        # yoki: pip install sentence-transformers faiss-cpu

# Ishga tushirish:
python server.py --port 8765
#   --no-llm    -> Ollama'siz ishlaydi (fallback rejim)
#   --no-memory -> xotira o'chirilgan
#   --model <nomi> -> boshqa Ollama modeli (masalan qwen3:4b)
# Modelni o'rnatish: ollama pull qwen3:8b   (qwen3 = haqiqiy fikrlash/thinking)
```

Status tekshirish:
```bash

```

## 4. web-ai-bridge (real Chrome + mr.wtin profili, CDP)

Bridge — Playwright orqali **haqiqiy Google Chrome**'ga ulanadi (chromium
yoki maxsus bo'sh profil emas). Ishlatiladigan profil: **mr.wtin** =
Chrome'dagi `Profile 1` (`twinm6142@gmail.com`).

### 4.1 Dependencies

```bash
cd web-ai-bridge/server
npm install
```

### 4.2 Sozlash — Igris_brain/mcp_servers.json -> "web_ai_bridge"

```json
"env": {
  "WAB_HEADLESS": "false",
  "WAB_BROWSER_CHANNEL": "chrome",
  "WAB_CDP_ENABLED": "true",
  "WAB_CDP_URL": "http://127.0.0.1:9222",
  "WAB_CDP_PORT": "9222",
  "WAB_CHROME_USER_DATA": "C:/Users/user/AppData/Local/Google/Chrome/User Data",
  "WAB_CHROME_PROFILE": "Profile 1"
}
```

### 4.3 Qanday ishlaydi (CDP rejim)

1. Bridge ishga tushganda avval `http://127.0.0.1:9222` da Chrome bor-yo'qligini
   tekshiradi.
2. Agar yo'q bo'lsa va `WAB_CHROME_USER_DATA` ko'rsatilgan bo'lsa — **real Chrome'ni**
   o'zi ishga tushiradi:
   `chrome.exe --remote-debugging-port=9222 --user-data-dir="...\Chrome\User Data" --profile-directory="Profile 1"`
   (mr.wtin profili — barcha loginlar/cookie'lar allaqachon bor).
3. **Chrome 136+ cheklovi**: `--remote-debugging-port` faqat *standart bo'lmagan*
   data-dir'da ochiladi. Shuning uchun bridge real `User Data` papkasiga
   **junction (katalog bog'lanishi)** yaratadi: `...\Google\Chrome-IGRIS-CDP` →
   real `User Data`. Chrome shu yo'l orqali ishga tushadi — debug port ochiladi,
   va real profil (mr.wtin) ostida jonli ishlaydi (cookie'lar/yozuvlar link orqali
   o'tadi).
4. Endpoint paydo bo'lgach `connectOverCDP` bilan ulanadi.
5. Bridge hech qachon Chromeni o'ldirmaydi — faqat ulanishni yopadi (`browser_close`
   dan keyin ham Chrome ochiq qolaveradi).

> **Muhim**: Chrome profili bir vaqtda faqat BIRTA instance'da ochiq bo'la oladi.
> Agar Chrome mr.wtin profili bilan allaqachon ochiq bo'lsa — uning BARCHA oynalarini
> yoping, keyin bridge'ni qayta ishga tushiring (yoki Chrome'ni o'zi
> `--remote-debugging-port=9222` bilan oching).

### 4.4 Tekshirish

```bash
cd web-ai-bridge/server
node e2e-driver.mjs          # E2E smoki (headless tarzda ishlaydi)
```

Agent/browser_info orqali:
```
Browser: chrome (CDP)
Mode: visible window
Connection: real Chrome via CDP (http://127.0.0.1:9222)
Chrome profile: "Profile 1" in C:\Users\user\AppData\Local\Google\Chrome\User Data
Data dir used by Chrome: C:\Users\user\AppData\Local\Google\Chrome-IGRIS-CDP (link to your real profile if the default dir was configured)
```

Qo'lda tekshirish (bridge'ni CDP rejimda sinash):
```bash
cd web-ai-bridge/server
WAB_CDP_ENABLED=true WAB_CHROME_USER_DATA="C:/Users/user/AppData/Local/Google/Chrome/User Data" \
WAB_CHROME_PROFILE="Profile 1" node -e "(await import('./src/browser.js')).getPage().then(p => { console.log('CDP ulandi:', p.url()); process.exit(0); })"
```
